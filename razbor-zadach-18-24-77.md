# Разбор SQL-задач 18, 24 и 77

В документе разобраны три независимых запроса из `1.sql`. Задачи 18 и 24 относятся к базе «Компьютерная фирма», задача 77 — к базе «Аэрофлот». Перед запуском выбирайте базу, к которой относится нужная задача.

## Задача 18. Самые дешевые цветные принтеры

**Нужно вывести:** производителя (`maker`) и цену (`price`) самых дешевых цветных принтеров.

### Запрос

```sql
SELECT DISTINCT
       Product.maker,
       Printer.price
FROM Product
INNER JOIN Printer
    ON Printer.model = Product.model
WHERE Printer.color = 'y'
  AND Printer.price = (
      SELECT TOP (1) price
      FROM Printer
      WHERE color = 'y'
        AND price IS NOT NULL
      ORDER BY price ASC
  )
ORDER BY Printer.price ASC;
```

### Как читать запрос

1. `SELECT DISTINCT Product.maker, Printer.price` задает два столбца результата: имя производителя и цену. `DISTINCT` убирает одинаковые пары, если в таблицах есть несколько строк с теми же производителем и ценой.

2. `FROM Product` начинает поиск в таблице с производителями и моделями. Но цены там нет, поэтому нужна еще таблица `Printer`.

3. `INNER JOIN Printer ON Printer.model = Product.model` соединяет производителя с его моделью принтера. `model` есть в обеих таблицах: по совпадающему номеру модели SQL сопоставляет строки.

4. `WHERE Printer.color = 'y'` оставляет только цветные принтеры. Значение `y` означает «да».

5. `Printer.price = (...)` оставляет только строки, цена которых совпала с результатом подзапроса в скобках.

6. Подзапрос `SELECT TOP (1) price FROM Printer ... ORDER BY price ASC` находит одну наименьшую цену. `ORDER BY price ASC` сортирует цены от меньшей к большей, а `TOP (1)` берет первое значение.

7. В подзапросе тоже стоит `WHERE color = 'y'`: минимум нужно искать именно среди цветных принтеров. `price IS NOT NULL` исключает неизвестные цены. В SQL Server `NULL` при сортировке по возрастанию может оказаться первым, хотя неизвестная цена не является самой дешевой известной.

8. `TOP (1)` находится внутри подзапроса и выбирает только значение цены. Внешний запрос затем находит всех производителей с этой ценой. Поэтому если несколько производителей делят минимум, они все попадут в ответ.

9. Последний `ORDER BY Printer.price ASC` только сортирует итоговые строки. Минимум он не вычисляет: это уже сделал внутренний `ORDER BY` вместе с `TOP (1)`.

### Зачем нужны два фильтра и `DISTINCT`

Цветовой фильтр внутри подзапроса выбирает правильный минимум. Цветовой фильтр снаружи не дает включить в ответ нецветный принтер, у которого случайно такая же цена. `DISTINCT` нужен потому, что один производитель может иметь несколько принтеров с одной и той же минимальной ценой, а в ответе требуется пара «производитель, цена», а не список физических экземпляров.

Не следует ставить `TOP (1)` во внешний запрос: тогда при одинаковой минимальной цене у нескольких производителей останется только один. Здесь один `TOP (1)` нужен, чтобы получить скалярное значение цены, а внешний запрос сохраняет все совпадения.

## Задача 24. Модели с максимальной ценой

**Нужно вывести:** номера моделей любого типа продукции, чья цена максимальна среди ПК, ноутбуков и принтеров.

### Запрос

```sql
WITH all_products AS (
    SELECT model, price
    FROM PC
    UNION ALL
    SELECT model, price
    FROM Laptop
    UNION ALL
    SELECT model, price
    FROM Printer
)
SELECT DISTINCT model
FROM all_products
WHERE price = (
    SELECT MAX(price)
    FROM all_products
);
```

### Как читать запрос

1. `WITH all_products AS (...)` создает общее табличное выражение (CTE) с именем `all_products`. Его можно воспринимать как временную таблицу, доступную только следующему запросу.

2. `SELECT model, price FROM PC` берет номер модели и цену каждого ПК.

3. Первый `UNION ALL` добавляет к этому списку модели и цены ноутбуков из `Laptop`; второй добавляет принтеры из `Printer`. `ALL` сохраняет повторяющиеся строки, это удобно: на этапе поиска общей максимальной цены важно собрать цены всех записей.

4. Основной запрос читает общий список: `FROM all_products`.

5. `SELECT DISTINCT model` задает требуемый результат — только номера моделей. `DISTINCT` удаляет повтор модели, если в исходных таблицах для нее было несколько записей.

6. Условие `price = (SELECT MAX(price) FROM all_products)` сравнивает цену каждой записи с самой большой ценой в общем списке. Подзапрос `MAX(price)` возвращает одно число; остаются все модели с этой ценой, в том числе если максимум разделяют несколько моделей.

Порядок мысли такой: сначала собрать в один список цены всех типов продукции, затем найти в нем максимум, затем вывести модель или модели с этой ценой.

## Задача 77. Максимум рейсов из Ростова по дням

**Нужно вывести:** максимальное число выполненных рейсов из Ростова за день и дату или даты, когда этот максимум был достигнут.

### Запрос

```sql
SELECT TOP (1) WITH TIES
       COUNT(DISTINCT Pass_in_trip.trip_no) AS flight_count,
       Pass_in_trip.date
FROM Trip
INNER JOIN Pass_in_trip
    ON Pass_in_trip.trip_no = Trip.trip_no
WHERE Trip.town_from = 'Rostov'
GROUP BY Pass_in_trip.date
ORDER BY COUNT(DISTINCT Pass_in_trip.trip_no) DESC;
```

### Как читать запрос

1. `FROM Trip` берет расписание рейсов. В этой таблице есть города отправления и прибытия, но нет дат, когда пассажиры летели.

2. `INNER JOIN Pass_in_trip ON Pass_in_trip.trip_no = Trip.trip_no` соединяет описание рейса с записями о перелетах. В `Pass_in_trip` есть дата. Один рейс в конкретный день может занимать несколько строк, потому что на нем летели разные пассажиры.

3. `WHERE Trip.town_from = 'Rostov'` оставляет только рейсы, вылетающие из Ростова.

4. `GROUP BY Pass_in_trip.date` собирает строки отдельно по каждой дате. После группировки можно посчитать число рейсов в каждый день.

5. `COUNT(DISTINCT Pass_in_trip.trip_no)` считает разные номера рейсов внутри дня. `DISTINCT` здесь принципиален: без него один рейс с десятью пассажирами посчитался бы как десять рейсов.

6. `AS flight_count` задает понятное имя столбцу с количеством рейсов.

7. `ORDER BY COUNT(DISTINCT Pass_in_trip.trip_no) DESC` сортирует дни от наибольшего числа рейсов к наименьшему.

8. `TOP (1) WITH TIES` оставляет первый, то есть максимальный по сортировке, результат и все строки с тем же количеством рейсов. Поэтому выводятся все даты, если максимум пришелся на несколько дней.

## Короткая памятка

- `JOIN ... ON` сопоставляет связанные строки двух таблиц.
- `WHERE` отбирает строки до группировки или итогового вывода.
- `ORDER BY ... ASC` сортирует по возрастанию, `DESC` — по убыванию.
- `TOP (1)` выбирает одну строку или одно значение; `WITH TIES` сохраняет равные значения на границе.
- `DISTINCT` удаляет повторы в выбранных столбцах.
- `COUNT(DISTINCT ...)` считает уникальные значения, а не все строки.
- `UNION ALL` складывает строки из запросов, не удаляя повторы.
- CTE, объявленный через `WITH`, дает имя промежуточному результату для следующего запроса.
